# Commit Hygiene

History is a debugging tool. A commit that mixes a rename with a behaviour change
cannot be reverted, bisected or reviewed; a subject that says "wip" makes every
future `git blame` a conversation. The discipline is cheap while committing and
expensive to reconstruct afterwards, which is why it belongs in the procedure, not
in the code review.

## When to Use

- Before opening a branch for review.
- When a bisect must find the commit that broke something.
- When a commit is about to contain two unrelated changes.
- When reverting one change would also revert another.

## When Not to Use

- Commits on a throwaway branch that will be squashed into one.
- Enforcing a message format a tool already enforces (the linter is the rule).
- Merge commits generated by the platform.

## Procedure

1. **One change per commit**, where a change is the smallest unit that can be
   reverted on its own. A formatting pass and a bug fix are two commits, always.
2. **Subject in the imperative, under ~72 characters, saying the why** when the what
   is obvious: "reject expired tokens" beats "update auth.py".
3. **Body explains what the diff cannot**: the constraint, the alternative rejected,
   the observable effect. If the body only restates the diff, delete it.
4. **Reference the issue and the contract version** when the change is contractual.
5. **Never commit generated artefacts, secrets or `.env` files**; if one got in, the
   fix is a rewrite of the commit, not a follow-up delete (history keeps it).
6. **Run the `commit-lint` tool** on the message list: it flags vague subjects, mixed
   concerns, oversized diffs, secret-shaped strings and missing references.
7. **Rewrite before pushing, never after** on a shared branch. Local history is
   yours; published history is everyone's.

## Exit Criteria

- [ ] Each commit is one revertible change, with a subject in the imperative.
- [ ] Bodies state what the diff cannot show; no body restates the diff.
- [ ] No commit mixes a rename, a move or a format with behaviour.
- [ ] No secret-shaped string and no generated artefact in the diff.
- [ ] `commit-lint` reports no vague subject and no mixed concern.
- [ ] Issue or contract reference present when the change is contractual.

## Common Failures

| Failure | Fix |
|---|---|
| "wip", "fix", "update" | Say the why: what becomes true after this commit |
| Rename + logic in one commit | Two commits; the rename first, with no behaviour change |
| Secret committed, then deleted | Rewrite the commit; deleting later leaves it in history |
| Squashing unrelated work "to be tidy" | The tidy unit is the revertible change, not the branch |
| Body repeats the file list | State the constraint and the rejected alternative |
| Rewriting a shared branch | Rewrite before pushing; after that, add a commit |
